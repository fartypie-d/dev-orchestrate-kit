# 공통 규칙 — 모듈 재사용·중복 방지 (전 도메인 적용)

> 모든 도메인 템플릿과 함께 적용한다. 위임 에이전트는 컨텍스트가 좁아
> **기존에 무엇이 있는지 모르면 새로 만든다.** 중복은 에이전트 실수가 아니라 지시서의 누락이다.
> 따라서 "찾는 일"은 위임받는 쪽이 아니라 **지시서를 쓰는 쪽의 책임**이다.

## 1. 지시서 작성 전 — 재사용 조사 (필수)

task를 쓰기 전에 **기존 자산을 먼저 찾는다.** 조사 없이 쓴 지시서는 중복을 만든다.

```bash
# 유사 기능·이름 검색 (동사·명사 양쪽으로)
grep -rn "핵심동사\|핵심명사" backend/ workers/ frontend/ --include="*.py" --include="*.ts" --include="*.vue"
# 공용 유틸 위치 확인
ls backend/app/{services,utils,core} workers/common/ frontend/composables/ 2>/dev/null
```

규모가 크거나 도메인이 낯설면 **`code-explorer` 에이전트**로 기존 실행 경로를 먼저 추적한다.

조사 결과는 셋 중 하나로 판정하고, **지시서 `재사용` 필드에 결론을 적는다**:

| 판정 | 의미 | 지시서에 쓸 내용 |
|---|---|---|
| **그대로 재사용** | 기존 모듈이 요구를 충족 | `재사용: <경로>의 <이름>을 import해서 사용. 새로 만들지 말 것` |
| **개선 후 재사용** | 기존 모듈에 인자·분기 추가하면 충족 | `재사용: <경로>의 <이름>을 확장. 기존 호출부 N곳이 깨지지 않게 할 것` |
| **신규 작성** | 유사 자산 없음 | `재사용: 없음 — <검색어>로 조사했으나 유사 모듈 없음` |

> **"없음"은 조사했다는 근거와 함께만 허용된다.** 필드를 비워두거나 생략하면 지시서 미완성이다.

## 2. 위임 프롬프트에 반드시 포함

1. `재사용` 필드 내용을 **그대로** 넣는다 (경로와 이름을 명시)
2. "**새 유틸·헬퍼 함수를 만들기 전에**, 지정된 기존 모듈에 같은 기능이 있는지 먼저 확인할 것"
3. "기존 함수를 복사해서 수정하지 말 것 — 확장이 필요하면 원본을 개선하고 호출부를 함께 갱신할 것"
4. "지시서에 없는 새 파일을 만들었다면 그 이유를 보고에 명시할 것"

## 3. 개선 후 재사용을 지시할 때

기존 모듈을 고치는 것은 **다른 호출부에 영향**을 준다. 지시서에 반드시 포함한다:

- 현재 호출부 목록 (`grep -rn "<함수명>"` 결과)
- 하위 호환 요구: "기존 호출부 N곳의 동작이 변하지 않아야 한다"
- 검증: 기존 호출부를 덮는 테스트가 통과해야 완료

호출부가 **5곳을 넘으면** 별도 task로 분리한다 (변경과 이관을 한 task에 담지 말 것).

## 4. 모듈 경계 (기존 규칙 유지)

재사용이라 해서 경계를 넘지 않는다. `module-boundary` 스킬의 MUST NOT이 우선한다:

- `backend/` ↔ `workers/` ↔ `frontend/` 간 **직접 import 금지** — HTTP API 또는 Redis Pub/Sub만
- 경계를 넘는 재사용이 필요하다면 그것은 "복사"가 아니라 **공유 계약(API·채널·이벤트 포맷) 추가**다
- `workers/common/`은 워커 3종의 공유 지점 — 여기 변경은 세 워커 전부에 영향

## 5. 검수 시 중복 검사 (리뷰어에게 지시)

리뷰어 호출 프롬프트에 항상 포함한다:

> "diff에 새로 추가된 함수·클래스·상수 각각에 대해, 같은 일을 하는 기존 코드가 있는지
> `grep`으로 직접 확인하라. 발견되면 🟠 이상으로 보고하고 재사용할 기존 경로를 제시하라."

diff만 보면 중복은 보이지 않는다 — **리뷰어가 저장소를 직접 검색해야 잡힌다.**

## Red Flags

| 합리화 | 현실 |
|---|---|
| "비슷한 게 있을 것 같지만 찾는 데 시간이 걸린다" | 찾지 않으면 중복이 확정된다. 조사는 지시서 작성자의 책임 |
| "기존 함수를 고치면 다른 데가 깨질 수 있으니 새로 만들자" | 그게 중복의 시작이다. 호출부를 세고 함께 갱신하거나, 별도 task로 분리 |
| "일단 복사해두고 나중에 합치자" | 합쳐지지 않는다. 지금 합치거나, 왜 못 합치는지 지시서에 쓴다 |
| "재사용 필드는 '없음'으로 두면 되겠지" | 근거 없는 '없음'은 조사 누락이다. 검색어를 함께 적을 것 |
