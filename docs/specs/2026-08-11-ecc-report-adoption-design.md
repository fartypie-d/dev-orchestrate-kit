# ECC 워크플로우 보고서 채택 설계 — G1·G2·G3 (2026-08-11)

**근거**: `~/docs/ECC_WORKFLOW_REPORT.md` (claude-code-g2 프로젝트, ECC 단독 실험 17세션·1,566테스트·28커밋).
보고서 권고 15건 중 절반은 현행 워크플로우에 기채택 상태(정량 3필드·세션 경계·HANDOFF·훅 헬스체크·
중복검사 강제 등). 실질 격차 4건 중 사용자 승인으로 **G1·G2·G3 채택**, G4(반려 재위임 시
opencode 세션 재개)·보조 3건(이벤트 세션 스탬프·파일 단위 커버리지·골든 테스트 기대치)은 보류.

## 채택 항목

### G1 — 전제 실측 (standard·large 필수)

지시서 작성 전, 계획이 의존하는 실제 코드 표면(함수 시그니처·타입·설정 키·픽스처 경로)을
Read/Grep으로 확인한다. 기억·문서·이전 지시서에서 온 전제는 실측 전까지 미검증 취급.
결과는 지시서 인덱스의 `## 전제 실측` 표(전제 → 근거 파일:라인 → 유지|뒤집힘)로 기록,
뒤집힌 전제는 해당 task 본문에 반영.

- 보고서 근거 §4.1: 계획 전제 실측이 재작업 3회 이상을 착수 전에 제거 — 가장 재현성 높은 값.
- 배선: SKILL.md 4단계에 소절 신설(재사용 조사 다음), Red Flags 1행 추가.

### G2 — 리뷰 예상 지점 RED 사전 고정 (standard·large 필수)

지시서 인덱스에 `## 리뷰 예상 지점` 표: 리뷰어가 🔴를 낼 가능성이 가장 높은 지점 1~3개 +
각각 착수 시점 RED 테스트(파일::테스트명, 담당 task). 해당 task의 `실패 테스트` 필드에 포함.

- 보고서 근거 §4.3: 사전 고정 도입 후 리뷰 3라운드 → 1라운드, 표본 4개 재현 — 실험 최대 발견.
- 배선: SKILL.md 5단계에 소절 신설, 6단계 위임 프롬프트 1번에 RED 포함 지시,
  7단계 리뷰어 전달물에 표 포함.

### G3 — 리뷰어 계약 3항 (전 등급, 리뷰어 호출 시 항상)

기존 중복검사 블록에 이어 모든 리뷰어 호출 프롬프트에 포함:

1. **완료 조건 대조** — task 완료 조건·리뷰 예상 지점 각각 충족 여부 명시 판정. 미충족·미언급은 🔴.
2. **자기 신고 재검증** — 위임 로그의 구현자 주장("해당 없음"·"이월 가능"·"통과")을 코드로 재검증.
   주장 인용만으로 판정 금지.
3. **재현 의무** — 🔴·🟠 지적에는 재현 경로(실행 명령+출력 또는 입력→결과 경로) 첨부.
   재현 없는 지적은 🟡로 강등.

리뷰어 전달물에 위임 로그 경로(`.orchestrate/task<N>.log`) 추가.

- 보고서 근거 §4.2: 완료 기준 절반 누락을 커버리지 100%·CRITICAL 0 상태에서 검출(①),
  구현자 "이월" 판정을 뒤집고 70곳 대신 7곳 최소 수선안 제시(②), 검출 결함 전부 재현 검증됨(③).

## 미채택과 사유

- **G4 세션 재개**: 반려 재위임의 fix 프롬프트는 현행도 리뷰 findings로 개선되나, 실행 세션은
  매번 신규. `opencode run -s <ID>` 재개는 가능함을 확인했으나 heavy tier 모델 승격 규칙
  (모델 교체 전제)과 충돌 — "1차 반려 같은 세션, 2차 heavy 새 세션" 절충안으로 후속 검토.
- **페이즈당 1커밋(§6-5)**: 현행 task별 커밋 + GATE 2 통합 승인이 롤백 입도에서 우월 — 역채택 안 함.
- **GateGuard류 제거 권고**: 현행 미사용이라 해당 없음.
